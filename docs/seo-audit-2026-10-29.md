# Paire web SEO implementation

Started October 29, completed October 30, 2026 (Asia/Kolkata). Applied the user-requested [AgriciDaniel/claude-seo](https://github.com/AgriciDaniel/claude-seo), installed 2.5.0, plus technical/sitemap/schema guidance and current Google primary documentation. All changes are local in `muse` on the existing branch. Existing untracked work and previous isolated audit branches were preserved. Nothing was committed, pushed, deployed or submitted to search engines. Native files, app/backend behavior and runtime sales/presence switches were not changed.

The live skill sitemap-discovery result was valid: HTTP 200 XML at `https://www.paire.in/sitemap.xml`, declared by robots.txt, with no warnings. The skill's live raw-HTML audit found 1,789 visible homepage words. These are pre-release observations, not a claim that Google has indexed every page.

## Architecture and truthful content

The existing architecture remains: core product pages, guides, comparison hub, 11 city guides, Work Circles, Date Duet, vibe quiz and a dated Diwali edition. No new city pages or generated keyword articles were added. Existing comparison statements and local suggestions still need periodic editorial verification against actual current sources; this task does not assert that every third-party feature or venue was independently checked.

Local missing-business-details builds emit **47 sitemap URLs**; seven legal/support pages are excluded until their variables are complete. Fully configured builds emit **54 URLs**. An expired Diwali edition is omitted from the discovery sitemap by the existing seasonal policy; its archive remains available. All retained pages keep crawlable internal links. Existing FAQs are preserved without claiming Google FAQ rich-result benefits. No invented reviews, ratings, business credentials or special AI-ranking schema were added.

llms files remain optional descriptive resources. Removing redundant named robots groups preserves the same public access through the wildcard group for Google and other compliant search bots, while applying the same private-path restrictions consistently.

## Dependencies and growth plan

1. Deploy only when requested. On production retain `PAIRE_SITE_URL=https://www.paire.in` and enable public indexing; verify the sitemap, representative headers and canonical metadata after deployment. Do not push the existing load-test branch blindly to main.
2. Verify the correct property in Search Console with real owner credentials/token; submit the sitemap. Inspect home, pricing, verification, a guide, a city, a circle and both tools. Monitor exclusions, canonical selection, impressions, queries and organic verified signups. No Search Console access or index state was assumed.
3. Maintain actual legal/support variables (`PAIRE_SUPPORT_EMAIL`, grievance contact, postal address and jurisdiction); the build must not invent these. Add an accountable operator/team biography and real author profiles using confirmed facts. Publish actual product captures and consented user stories rather than stock testimonials or verification overclaims.
4. Measure deployed mobile LCP/INP/CLS in PageSpeed/CrUX and Search Console where sufficient field data exists. No field CWV or Lighthouse performance score was measured. Current local fonts are about 88 KB each and public CSS about 16 KB; asset sizes alone do not prove good field performance.
5. Prioritize real search intent: clear pricing and messaging eligibility; what email/photo/work badges prove; how Date Duet works; public first-date planning; privacy controls and dating scams. Improve these existing pages with actual evidence before expanding city/sector pages. Update comparisons from named primary sources and attach real review dates only when checked.
6. Use genuine partnerships, community participation and useful product tools to earn relevant mentions. Track organic entry → app open → verified signup using existing privacy-preserving metrics. User trust, external references, demand and rankings require ongoing work; none can be fabricated with tags.
